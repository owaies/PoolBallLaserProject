# Contributing to PoolBallLaserProject

Make changes that are focused, testable, and consistent with the existing architecture.

## Development workflow
1. Create a focused branch.
2. Reproduce the issue or define the expected behavior.
3. Implement the smallest coherent change.
4. Run the project's available lint, build, test, or validation checks.
5. Commit related changes separately with descriptive messages.

## Safety
- Never commit API keys, passwords, tokens, or local environment files.
- Preserve existing user data and authentication boundaries.
- Avoid unrelated rewrites when fixing a specific problem.
- Update docs when externally visible behavior changes.

## Pull requests
State the problem, summarize the implementation, list verification steps, and call out limitations.
